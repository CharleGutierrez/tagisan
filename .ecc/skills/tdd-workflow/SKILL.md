# TDD Workflow Skill

## Philosophy
Code is not complete until proved by automated, deterministic tests.

## Rules
1. Never write implementation code without a failing test first.
2. Formulate tests that stress boundaries: zero values, empty collections, maximum sizes, concurrency races.
3. Keep tests fast, independent, and free of external network calls.
